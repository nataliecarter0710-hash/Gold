# Diagnostic-only runtime

`npm run start:diagnostic` starts `src/diagnostic-server.js`, a separate process that exposes only `GET /api/health`, authenticated `GET /api/diagnostics/schema` and 404 for other paths. The schema endpoint returns metadata only (table/column/type/nullability and missing mapping assumptions); it does not read application rows or perform writes. It does not import the operational round router or Supabase admin client. Set `DIAGNOSTIC_TOKEN` and a least-privilege, read-only `DATABASE_URL` in the diagnostic service environment if you want to enable the schema endpoint; otherwise health remains available and schema diagnostics return disabled/unavailable. Do not configure this command as the start command for `goldbet9-api-staging` unless intentionally deploying a separate diagnostic service. That service remains health-only; no bet/coin/settlement operations are enabled here.

The four-table contract in `src/db/schemaMapping.js` is tentative and exists only to compare metadata. Run `scripts/check-schema-columns.sql` manually in read-only mode to inspect columns, constraints and indexes for `game_sessions`, `coin_ledger`, `virtual_coin_ledger`, and `round_settlements`. No migration is provided or run.

Smoke check the diagnostic process locally with `npm run start:diagnostic` and `curl http://localhost:${PORT:-3000}/api/health`. With `DIAGNOSTIC_TOKEN` and read-only `DATABASE_URL` configured, call `/api/diagnostics/schema` using `Authorization: Bearer <token>`. This is a metadata diagnostic only, not a round or settlement smoke test.
